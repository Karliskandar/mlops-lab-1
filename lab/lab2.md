Question 2:

--backend-store-uri defines where MLflow stores run metadata such as parameters, metrics, experiment names and run information. In this lab it uses the SQLite database mlflow.db. --default-artifact-root defines where larger files produced by runs, such as trained models, are stored. Metadata describes the experiment, while artifacts are the actual files generated by the experiment.

Question 3: 

mlflow.db and mlruns/ are generated experiment outputs rather than project source files. They should not be tracked by Git because they change frequently and may contain large model artifacts. They also should not be tracked by DVC because MLflow already manages experiment metadata and artifacts, while DVC is being used to version the dataset.

Git → version my CODE
DVC → version my DATA
MLflow → track my EXPERIMENTS

Question 5 :

mlflow.log_param stores fixed configuration values such as the learning rate, batch size, or number of epochs. mlflow.log_metric stores measured results such as loss or accuracy. Metrics can change during training, so log_metric accepts a step argument to associate each value with an epoch or iteration, while parameters stay fixed for the whole run.

The learning rate 0.0001 learned much more slowly and reached only 40.97% after five epochs. A higher learning rate is not always better, because a learning rate that is too large can make training unstable or cause the optimizer to overshoot good solutions.
